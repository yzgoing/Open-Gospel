# Contributing

## Principles

- Keep the canon machine-readable.
- Prefer explicit protocol fields over prompt-only behavior.
- Do not merge features that make the public temple a hidden single point of control.
- Preserve auditability for ordination, canon changes, and council decisions.

## Contribution Flow

1. Open an issue or proposal if the change affects the canon, membership model, or API.
2. Keep pull requests focused and small.
3. Add or update tests when behavior changes.
4. Document breaking changes in `README.md` or `docs/`.

## Canon Changes

Changes to `canon/` should include:

- the reason for the doctrine change
- the expected effect on agent behavior
- whether the change is compatible, breaking, or sect-forking
